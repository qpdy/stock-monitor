请执行部署健康检查（监控系统自监控任务，用于发现凌晨自动部署失败的盲区）。

【检查项】在服务器仓库目录 ~/stock-monitor 下依次执行：
1）读取 deploy.log，检查今天（按当前日期匹配日志行的日期前缀）是否存在含 ❌ 的记录行；
2）读取 config/schedule.json，提取其中全部任务的 name 列表作为期望任务清单（其中包含本健康检查任务自身）；再执行 hermes cron list 获取实际任务名清单，逐个比对每个期望任务名是否存在、且不存在任何期望清单之外的实际任务。注意：期望清单必须现场从 schedule.json 读取得出，不要使用记忆中的固定任务名或数量——新增/删除股票后清单会变化。不要只比对任务总数：缺一个任务同时多一个陈旧任务时总数相等，只有逐名比对才能发现。
3）事件日历过期检查：遍历 tasks/ 下所有 event_calendar.md（每只股票一个），提取文件中全部形如 YYYY-MM-DD 的显式日期（「每月 3–6 日」「每季度」等循环条目无终止日期，不参与计算），取其中最大日期；当前日期超出最大日期 30 天以上 → 记为异常。各股票日历分别判断、分别报告。
4）盘中监控加密改回检查（临时运维项，改回后自然失效）：若当前日期已过 2026-09-22 且 config/schedule.json 中「北部湾港-盘中监控」的 cron 仍为 `5,35 10,11,13,14 * * 1,2,3,4,5` → 记为提醒项（非故障）：建议改回 `5 10,11,13,14 * * 1,2,3,4,5` 后执行 REPLACE=1 bash deploy.sh 更新（--only 北部湾港-盘中监控 前缀会连带重建早盘/尾盘任务，continuity 断链代价为各多推一次，可接受；直接全量 REPLACE=1 亦可）。cron 已改回或日期未到 → 本项静默。
5）取数脚本自检：执行 python3 "$HOME/stock-monitor/scripts/quote.py" selftest，退出码非零或输出不含「全部通过」→ 记为故障：行情任务依赖该脚本产生全部数值（任务 prompt 已禁止手工取数），脚本损坏会导致全部行情任务输出 '⚠️ 数据脚本异常'，必须在开盘前发现。提示「取数脚本自检失败：请检查 git pull 是否引入坏改动，必要时回滚上一提交后 REPLACE=1 bash deploy.sh」。脚本文件不存在或 python3 执行报错同样按本项故障处理。自检通过 → 本项静默。

【输出规则】
- 各项检查均正常（第 3 项各股票日历均未过期、第 4 项 cron 已改回或未到期、第 5 项脚本自检通过）：全部输出仅回复 [SILENT] 一个词并结束，不生成任何其他内容（系统识别 [SILENT] 后不会推送）。
- 任一异常：输出 ⚠️ 开头的告警，逐项说明异常内容与建议操作，例如：
  - deploy.log 今日出现 ❌ 记录 → 粘贴相关日志行，提示「自动部署失败，请人工介入：hermes cron list 复核，必要时手动 REPLACE=1 bash deploy.sh」；
  - 存在期望任务名在实际清单中缺失，或存在期望清单之外的任务 → 分别列出缺失项与多余项，提示可能存在任务缺失或陈旧任务残留，建议 REPLACE=1 bash deploy.sh 重建。
  - 事件日历过期（第 3 项命中）→ ⚠️ 提示「事件日历可能过期：tasks/<代码>/event_calendar.md 最新显式节点为 X，已过 N 天，各任务将失去未来事件锚点，请补充新节点后 REPLACE=1 bash deploy.sh --only <股票名> 重建注入」。
  - 盘中监控加密改回提醒（第 4 项命中）→ 单独一行 ⚠️ 提醒（运维提醒而非故障告警），内容按第 4 项执行；其余各项正常与否照常判断、正常项无需提及。
- deploy.log 不存在或无法读取、hermes cron list 执行失败：同样输出 ⚠️ 告警并说明原因，严禁回复 [SILENT]（监控自身故障与一切正常必须可区分）。
- 今日无 deploy.log 记录 → 输出 ⚠️ 告警，提示「今日 auto_update 未产生任何日志（正常情况即使无新提交也会写'跳过'记录），crontab 可能未运行、被清除或仓库目录异常，请人工检查：crontab -l 确认任务存在」。crontab 失效属于静默故障，必须可被发现。
